1. Three-Tier API-Led Integration Architecture

To eliminate bottlenecks and avoid mobile application lag during complex mathematical optimization, ClassSync applies Gartner's API-Led Integration standard across three tiers:

  • Experience API Layer (Gateway / BFF): Lightweight mobile endpoints (/api/v1/mobile/*) that strip out heavy desktop administrative payloads, returning only actionable schedule streams and room occupancy cards.
  • Process API Layer (Business Orchestration): Encapsulates the Google OR-Tools CP-SAT constraint engine, independent timetable validation routines, and schedule publication managers.
  • System API Layer (Data Access & Hardware Boundaries): Encapsulates isolated database operations across relational databases and Firebase Cloud Firestore, enforcing strict Zero-Trust boundaries.

B. Pre-Computation Demand vs. Supply Formula

Before automated AI/solver generation begins, the system verifies feasibility using the following formulas:

1. TOTAL LECTURE CONTACT HOURS DEMAND: Demand_Lec = SUM(Sections_i * Subject_LecHours_i) 2. TOTAL LAB CONTACT HOURS DEMAND: Demand_Lab = SUM(Sections_i * Subject_LabHours_i) 3. ROOM OPERATING SUPPLY: Supply_Rooms = Total_Usable_Rooms * Weekly_Operating_Hours (72 hrs: Mon-Sat 7AM-7PM) 4. FEASIBILITY RATIO CHECK: Utilization_Ratio = Demand_Hours / Supply_Hours --> IF Utilization_Ratio > 1.00: Status = INFEASIBLE (Deficit Alert Generated) --> IF Utilization_Ratio <= 0.85: Status = OPTIMAL (Generation Permitted)

C. Health, Fatigue & Lunch Break Constraints

  • Mandatory Lunch Protection: A continuous 60-minute break is guaranteed between 11:30 AM and 01:30 PM for both teachers and students. No single class can span through this period without a split.
  • Consecutive Teaching Cap: No teacher or student section can be scheduled for more than 4.5 continuous hours (3 consecutive 1.5-hour subjects) without a mandatory minimum 30-minute rest window.
  • Passing Time Buffer: Automatic 15-minute travel buffers are inserted between room changes across different campus floors or buildings.

3. Irregular Students, Backload Clearing & Section Slot Infiltration

THE ADVISORY REQUIREMENT: REGULAR VS. IRREGULAR ENROLLMENT
Regular students follow a pre-calculated, conflict-free block schedule. In contrast, irregular students cannot self-enroll freely. They carry backload units, failed prerequisites, and retakes. They must undergo formal Program Head Academic Advising.

A. The 3-Step Irregular Advising & Enrollment Process

  1. Evaluation & Advising Slip Generation: The Program Head opens the Advising Portal (/admin/advising), reviews the student's deficiency transcript, verifies cleared prerequisites, and authorizes an approved subject list with an official maximum unit cap (e.g., maximum 18 or 21 units).
  2. Mobile Subject & Slot Selection: The student logs into the Mobile App, where only the approved subjects appear. The student can select open slots in regular block sections (e.g., join BSIT-3A for major subjects) and cross-enroll into lower-year sections (e.g., join BSIT-1B for backload subjects).
  3. Real-Time Dynamic Guardrail Verification:
    • Room Seat Availability Guardrail:
      Available_Irreg_Slots = Classroom_Physical_Capacity - Regular_Block_Count Example: Room Capacity = 45 | Regular Enrollees = 38 --> 7 Available Slots
      If open slots = 0, the section is locked as FULL, protecting physical room capacity.
    • Cross-Year Clash Prevention: If a 3rd-year major subject overlaps in time with a 1st-year retake, the solver alerts immediately and suggests conflict-free alternative sections.
    • Overload Ceiling Check: Total selected units cannot exceed the Program Head's authorized limit without an approved Dean's Overload Permit.

B. Special Accommodations (Working Students & Safety Separations)

  • Working Student Shift Anchoring: Accommodates verified BPO or daytime employment schedules by restricting section suggestions to afternoon/evening slots.
  • Anti-Bullying / Disciplinary Mutual Exclusion: Hard constraint enforcing:
    CONSTRAINT: Student_A.Section_ID != Student_B.Section_ID (Enforced across all classes)
